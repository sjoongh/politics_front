# 브리핑 코리아 이슈 중심 전면 개편 — 설계

작성일: 2026-11-10 (v2, codex 교차 검토 17건 반영)
대상 레포: `politics_front`(React 19 / CRA / Capacitor / Firebase Hosting) + `politics_backend`(FastAPI / Firestore / Vercel 서버리스)
상태: 사용자와 구조 합의 완료(2026-11-10). 이 문서는 플랜 작성의 입력이다.

**사용자 결정(2026-11-10)**
- **무료 유지 확정.** Firestore Spark(읽기 5만/일)와 Gemini 무료 티어(프로젝트당 하루 20건, `utils/gemini_rest.py:85`) 안에서 운영한다. 유료 전환은 하지 않는다. 따라서 설계는 읽기 예산과 AI 호출 예산을 하드 제약으로 둔다(§6.0). 사용자가 미리 해야 할 선행 작업은 없다.
- 병합·자동 연결 승인: codex 교차 검토로 갈음한다(내 판단). 단 병합 실행 직전에 dry-run 요약(병합 쌍 수와 대표 예시)을 사용자에게 한 번 보여 주고 진행한다.

## 1. 의도와 이유

브리핑 코리아는 2026-06에 제품 축을 "뉴스 어그리게이터"에서 "1차 소스 맥락 엔진"으로 옮겼다. 한 이슈에 대해 정부는 무엇을 말했고, 국회에는 어떤 법안이 있고, 누가 어떻게 표결했고, 언론은 어느 쪽에서 얼마나 다뤘는지를 한 자리에 놓는 것이 차별점이다.

현재 UI는 그 이전 제품의 문법 그대로다. 기본 탭이 뉴스, 홈은 그라데이션 히어로와 피처드 기사 카드, 탭 7개 중 이슈는 6번째, 1차 소스는 이슈 카드를 눌러야 열리는 모달 안쪽에 있다. 제품 소유자의 평가는 "전반적으로 다 별로고 제품 목적과 안 맞는다"이며, 원하는 것은 "가독성과 가시성을 올리는 UI/UX"다.

문제는 화면 구조와 데이터 두 층에 걸쳐 있다(2026-11-10 라이브 측정).

| 항목 | 측정값 |
|---|---|
| 이슈 상세 1건 응답 시간 | 33초 |
| 상위 이슈 20개의 정부·법안·표결 소스 합계 | 1건 · 0건 · 0건 |
| 이슈 65개 구성 | 뉴스 자동군집 52 · 법안 11 · 수동 2 |
| 이슈당 연결 기사 수 | 6~160건 |
| 쌓여 있는 1차 소스 | 정부 발표 199 · 표결 108 · 법안 2,869 |
| 사용자 데이터 | 사용자 1명 · 북마크 0건 |

따라서 **프론트 구조·시각 개편과 백엔드 데이터 보강을 한 묶음**으로 진행한다. 사용자가 명시적으로 "전부 다" 범위를 선택했다. 1차 소스 재료는 이미 충분히 쌓여 있고, 문제는 연결이다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 앱을 열면 "지금 무슨 이슈가 있고, 공식 기록이 있는지, 확인된 입장은 무엇인지"가 첫 화면에서 읽힌다.
- 이슈 상세가 2초 안에 열리고, 공식 기록 → 입장 → 타임라인 → 보도 순으로 스크롤만으로 읽힌다.
- 뉴스는 이슈 아래 증거로 내려간다. 뉴스 탭은 없앤다.
- 이슈 목록에서 같은 사건이 둘로 보이지 않고, 요약이 빈 템플릿 문장이 아니다.
- 1차 소스(정부 발표·법안·표결)가 뉴스 이슈에도 붙는다. 단, **오연결 0건이 중복 0건보다 우선**한다.
- 모바일(Capacitor 앱)과 데스크톱 웹이 같은 컴포넌트로 폭에 따라 다른 배치를 쓴다.

**비목표**
- 로그인·북마크·관심사·알림·마이페이지의 기능 변경. 외관만 새 토큰에 맞춘다. **이슈 저장(북마크) 기능은 이번 범위 밖**(현재 북마크는 기사 전용, 라이브 0건).
- 새 데이터 소스 추가(정당 공식 입장, 시민행동, 일정 캘린더 등). 기존 수집 범위 안에서 연결만 보강한다. 따라서 "다음 일정" 같은 예정 정보는 넣지 않는다.
- iOS 빌드·스토어 제출. Android AAB 빌드까지는 범위에 포함한다.
- Firestore·Gemini 유료 전환. 무료 한도가 설계의 하드 제약이다.

**반목표(이렇게 되면 실패)**
- 색·모서리·그림자만 바뀌고 홈이 여전히 뉴스 피드인 결과.
- 새 구조가 빈 1차 소스 칸을 더 크게 보여 주는 결과. 공식 기록이 없으면 "없음"이 정직하게, 작게 보여야 한다.
- 근거보다 강한 정치적 결론을 UI가 만들어 내는 것. 표결 다수를 정당 공식 입장으로, 법안 작성 주체를 주장 주체로 표시하면 실패다.
- 제목·메뉴를 반복하는 소개문, 부제, 슬로건, "~를 관리합니다"류 안내문이 들어가는 것.
- 상세 응답이 여전히 5초를 넘는 것. 파이프라인이 Firestore 무료 읽기 한도(일 5만)를 넘어 429로 앱이 흔들리는 것.

## 3. 제약

- 프론트: CRA(react-scripts 5), React 19, Pretendard 자체 호스팅, lucide-react, MUI는 로그인·마이페이지·알림 폼에서만 사용 중. 라우터 없음(탭 state + `?issue=`·`?article=` 딥링크). Firebase Analytics(GA4) 계측 있음. Capacitor 뒤로가기 리스너는 **현재 없음**.
- 앱: Capacitor 7, Android 배포 중(versionCode 13, targetSdk 36). 공유 링크는 백엔드 `/share/issue/{id}`가 OG 카드를 내고 프론트 `?issue=`로 리다이렉트한다. **이 딥링크는 계속 동작해야 한다.** 공유 라우터는 이슈 문서를 직접 읽는다(`routers/share_router.py:65`).
- 백엔드: Vercel 서버리스 1함수, 동기 Firestore 클라이언트를 `async def` 안에서 호출 중. 리전 미설정(기본 US). Firestore `(default)`는 **asia-northeast3(서울)로 확인**(2026-11-10 REST `databases.list`). Firestore 무료 티어(읽기 5만/일) 429 간헐 발생. Gemini는 무료 키(gemini-2.5-flash 전용), 일일 쿼터가 작고 소스 보강·이슈 요약·검색 브리핑이 같은 쿼터를 나눠 쓴다.
- 데이터 사실: `gov_policy.published_at`은 ISO 시각이 채워져 있고 `actor_name`은 "대한민국 정부(정책브리핑)" 고정(부처 없음). `assembly_vote.published_at`은 표결일, `assembly_bill.published_at`은 발의일. 법안 소스는 `actor_name="국회"`, `position="propose"`로 정규화돼 있어 **입장으로 쓰면 안 된다**(`utils/source_item.py:73`). 기사 `published_at`은 수집 시각이다.
- 설치 안 됨: `react-router`, `@capacitor/app`(둘 다 신규 의존성).
- `source_items.published_at` 형식이 정부(ISO UTC)와 국회(`YYYY-MM-DD`)로 다르다. KST 일자 경계는 정규화 함수 하나로 처리한다.
- 파이프라인: GitHub Actions `news-collect.yml` 매시 5분. 수집 → 소스 적재 → 보강 → 법안 이슈 생성 → 링크 → 크로스링크 → 뉴스 이슈 생성 → 요약 → 의원 보강.
- 테스트: 백엔드 pytest 26파일, 순수 로직만. 프론트는 `CI=false npm run build` + Playwright 스크린샷으로 검증해 왔다.
- 작업 규약: 구현·설계는 codex와 교차 검토한다. UI 문구는 `~/.claude/CLAUDE.md` "제품 UI 문구" 절을 따른다.

### 4.1 라우트와 이력

`react-router` v7 `BrowserRouter`. Firebase Hosting은 이미 SPA rewrite.

| 경로 | 화면 |
|---|---|
| `/` | 오늘(KST 오늘 판) |
| `/today/:date` | 특정 날짜 판(YYYY-MM-DD) |
| `/issues` | 이슈 피드 |
| `/issues/:id` | 이슈 상세 |
| `/members`, `/members/:id` | 의원 목록·상세 |
| `/search` | 검색과 둘러보기 |
| `/me` | 로그인 또는 마이페이지(맞춤 피드 포함) |

호환: `/?issue=<id>` → `/issues/<id>`, `/?article=<id>` → `/` + 기사 리더 열기. 둘 다 `replace`로 처리해 뒤로가기에 남기지 않는다. 병합된 이슈 id는 백엔드가 대상 이슈를 돌려주므로 프론트는 응답의 `id`로 URL을 `replace`한다.

**뒤로가기 규칙(Android 하드웨어·브라우저 공통)**, 우선순위 순:
1. 열린 모달(기사 리더, 로그인)이 있으면 모달만 닫는다.
2. 앱 내부 이력이 있으면 라우터 back.
3. 상세로 직접 진입해 내부 이력이 없으면 해당 목록(`/issues` 또는 `/members`)으로 `replace`.
4. 탭 루트에서는 앱 종료(Capacitor `App.exitApp`), 웹에서는 브라우저 기본.
- 데스크톱 분할 화면에서 목록 행을 연속 선택할 때는 `replace`로 URL을 바꿔, 뒤로가기가 이전 이슈가 아니라 목록 단독 상태로 돌아가게 한다.
- 목록 → 상세 → 뒤로가기 시 목록 스크롤 위치와 필터를 복원한다(라우트 state 또는 세션 저장).

### 4.2 오늘 (`/`, `/today/:date`)

데이터는 §6.7의 **판(edition) 문서 하나**에서 온다. 위에서 아래로:

1. **날짜 헤더**: 날짜와 요일, 좌우 날짜 이동. 호수·슬로건 없음. 판에 `overview`가 있으면 한 줄, 없으면 생략.
2. **오늘 변화한 이슈 최대 3개**: 같은 고정 틀. 상태·카테고리 배지 → 제목 → "무슨 일"(판에 저장된 그날의 요약 1~2문장) → "확인된 입장"(§6.2 기준, 있을 때만, 최대 3개) → "공식 기록"(그날의 표결 결과 또는 정부 발표·법안 수 한 줄). 값이 없는 행은 통째로 생략.
3. **국회 오늘 · 정부 오늘**: 기본은 각각 **한 줄 요약 + 펼치기**("본회의 표결 7건 · 발의 12건", "정책브리핑 5건"). 펼치면 표결은 법안명 + 찬반기권 막대 + 수치 + 연결 이슈 링크, 발의 법안과 정부 발표는 제목 행. 절차성 안건은 "그 밖 N건"으로 접는다. 건수 0이면 줄 자체를 생략.
4. **이슈 피드**: §4.3과 동일한 전체 행. 상위 3개는 제외. 과거 날짜 판에서는 그날 판에 기록된 이슈 목록을 보여 준다.

판에 상위 이슈가 없으면(휴회일·데이터 공백) 날짜 헤더 바로 아래 이슈 피드가 온다. 빈 상태 안내문은 넣지 않는다.

### 4.3 이슈 피드 (`/issues`)

- 상단: 필터 칩(**전체 / 공식 기록 있음 / 표결 있음 / 정부 발표 있음 / 진행중 / 가결**) + 정렬(**주목도순 / 갱신순 / 보도 많은 순**). 필터·정렬은 서버 계약(§6.2)이며 커서 페이지네이션(50건)이다. 제목 검색 입력은 두지 않는다. 검색은 검색 탭이 맡는다.
- **이슈 행**(카드 아님, 헤어라인 구분), 과밀을 피하기 위해 4줄로 제한:
  1. 상태 배지 · 카테고리 배지
  2. 제목
  3. 한 줄 요약(2줄 클램프)
  4. 소스 줄: `정부 2 · 법안 1 · 표결 182:61 · 보도 52` + 우측 갱신일. 표결은 대표 표결 1건(§6.2)의 수치이며 탭하면 법안명이 툴팁·상세에서 보인다. 정부·법안·표결이 모두 0이면 `공식 기록 없음`을 흐리게 쓰고 보도 수만 남긴다.
  - 확인된 입장이 **공식 발표 또는 표결 근거**로 2개 이상 있을 때만 3줄과 4줄 사이에 입장 칩 최대 2개를 넣는다. 보도 추출 입장은 행에 넣지 않는다.
  - 보도 성향 막대는 행에 넣지 않는다(상세에서만).
- 법안 이슈(`issue_bill_*`)는 같은 행 형식, 제목은 `law_name`, 원제목의 "(대안)(○○위원장)"은 보조줄.

### 4.4 이슈 상세 (`/issues/:id`)

위에서 아래로, 앵커 탭으로 점프:

1. 헤더: 뒤로 · 공유. 상태·카테고리 배지, 제목, 한 줄 요약. 자동 생성 이슈면 기존 고지 한 줄.
2. **공식 기록** (먼저 온다): 표결(법안명, 날짜, 찬반기권 막대 + 수치 + 결과, 정당별 펼침), 법안(법안명, 제안자, 단계, 발의일), 정부 발표(제목, 날짜, 발췌). 시간 역순 한 목록, 유형은 행 머리 라벨. 모두 0이면 `공식 기록 없음` 한 줄.
3. **입장표**: 행 = 행위자, 열 = 입장 + 근거 한 줄 + **근거 유형 라벨**(`공식 발표` / `표결` / `보도`). 표결 기반은 "민주당 투표자 중 찬성 N · 반대 M"처럼 관측치로 쓴다. 각 행은 근거 소스로 링크. 확인된 입장이 없으면 섹션 생략.
4. 앵커 탭: **공식 기록 N · 입장 N · 타임라인 N · 보도 N**. 0인 탭은 비활성.
5. **타임라인**: 수동 이슈의 `events` + 연결된 공식 기록의 날짜(발의·표결·정부 발표)를 합쳐 자동 생성. 항목 2개 미만이면 생략.
6. **보도**: 제목을 "수집된 보도 분포"로 한다. 막대는 진보·중도·보수·외신·미분류 5구간, 범례에 건수. 사각지대 문구는 "수집된 보도 중 ○○ 성향 매체 없음"으로 한정한다(보도하지 않았다고 단정하지 않는다). 그 아래 성향별 기사 압축 행(제목·매체·날짜), 탭하면 기존 인앱 리더. 초기 30건, "더 보기"로 커서 페이지.
7. **발의 의원**: 연결된 법안의 제안자 중 의원 문서와 이름이 일치하는 사람만 칩으로(최대 8). 표결 참여자는 나열하지 않는다. 없으면 생략.

### 4.5 의원 (`/members`, `/members/:id`)

- 목록: 기존 검색·정당 필터·정렬 유지(300명, 클라이언트 필터). 행 형식, 정당은 좌측 2px 색 띠와 텍스트. 전과·선수는 숫자 텍스트. 사진 36px 원형.
- 상세: 프로필 줄 → **표결 요약**(찬/반/기권/불참 수와 막대) → 주요 표결(법안명 + 본인 표 + 연결 이슈 링크, §6.6) → 발의 법안 → 전과(확정 판결). 섹션은 데이터 있을 때만.

### 4.6 검색 (`/search`)

- 입력 하나. 결과는 세 묶음, 위에서부터 **이슈 · 의원 · 기사**.
  - 이슈·의원: 이미 로드된 카탈로그(이슈 목록 첫 200건의 제목·요약·키워드, 의원 300명 이름·지역구)에 대한 클라이언트 키워드 일치. 네트워크 없음.
  - 기사: 기존 AI 자연어 검색(`useAiSearch`)과 폴백 그대로. 브리핑 생성 버튼 유지.
- **둘러보기**: 입력이 비어 있을 때 "법안·표결", "정부 발표" 두 항목. 각각 §6.8의 소스 목록 API를 날짜 역순 커서로 보여 주는 단순 목록(제목·날짜·연결 이슈 링크). 유형 필터(표결만 / 발의만).

### 4.7 데스크톱(≥1024px)

- 상단 바: 브랜드 텍스트, 탭 4개, 우측 검색 입력·테마·로그인. 부제 삭제.
- `/issues`·`/members`: 상세 미선택 시 **단일 칼럼 목록**(최대 폭 760px). 행 선택 시 좌 목록(~440px) + 우 상세로 전환. 상세 닫기 버튼으로 단일 칼럼 복귀.
- `/`, `/search`: 단일 칼럼 최대 폭 760px.
- 768~1023px: 모바일 레이아웃에 좌우 여백만.

### 4.8 없애는 것

- 탭: 전체, 뉴스, 대통령, 정책, 정치인 발언, 맞춤. 하단 탭은 4개 고정.
- 홈 히어로, 피처드 카드, 토픽 칩, "더 많은 뉴스", 섹션 제목 이모지, 헤더 부제, 모달형 상세.
- "맞춤"(`ForYouFeed`)은 `/me` 안의 섹션으로 이동(로그인 사용자만).
- 대통령·정책·발언 데이터(`presidents`, `parliamentary_activities`, `political_statements`)는 화면에서 빠진다. 백엔드 엔드포인트는 유지. **(내 판단: `gov_policy`가 정부 발표를 대신한다. 세 컬렉션을 이슈에 연결하는 작업은 범위 밖.)**

## 6. 백엔드 변경 (결정됨)

조사 근거는 2026-11-10 코드 추적. 파일:줄은 당시 기준.

### 6.0 공통 원칙

- **읽기 예산(하드)**: 기존 파이프라인은 실행당 약 2,500건을 읽는다(뉴스 이슈 생성 400기사+전 이슈+의원, 크로스링크 300기사+500소스, 법안 이슈 300기사+1,500소스). 매시 돌리면 하루 6만으로 무료 한도(5만)를 넘는다. 대책 세 가지를 모두 적용한다. (1) **실행 내 공유 로더**: 기사 400건·활성 이슈 전체·최근 14일 소스를 실행당 한 번만 읽고 모든 단계가 공유한다(`PipelineContext`). (2) **주기 분리**: 뉴스 RSS 수집은 매시, 소스 적재·보강·이슈 생성·링크·digest·판 같은 무거운 단계는 **3시간마다**(KST 0,3,6,…시). (3) digest·판 계산은 메모리에 올린 문서만 쓰고 이슈별 기사 재조회를 하지 않으며, 변화 없는 문서는 쓰지 않는다. 목표: 무거운 실행 1회 읽기 **2,000건 이하**(하루 8회 = 1.6만), 사용자 조회 몫 3만 이상 확보. 실행당 읽기 수는 로그로 남긴다. digest·판 계산은 **그 실행에서 이미 메모리에 올린 문서만** 쓰고, 이슈별로 기사를 다시 읽지 않는다. 변화 없는 문서는 쓰지 않는다.
- **Gemini 예산(하드)**: 하루 20건. 환경변수 `GEMINI_DAILY_BUDGET`(기본 18, 여유 2) 하나를 모든 호출이 공유한다. 배분: 이슈 요약 최대 10, 소스 보강 최대 8, 보도 기반 입장 추출은 **기본 비활성**(`STANCE_PRESS=0`), 검색 브리핑은 기존처럼 캐시 적중만. 하루 20건이면 이슈 요약은 새 이슈 기준 하루 10개, 기존 템플릿 이슈 52개는 약 5일에 걸쳐 채워진다. 그 사이 표시되는 요약은 §6.5의 규칙 기반 대체 요약이다(템플릿 문장 금지). 우선순위는 이슈 요약 > 소스 보강 > 입장 추출 > 검색 브리핑. 429를 받으면 그 실행의 남은 호출을 중단하고 상태만 기록한다. 결과는 **입력 근거 해시**와 함께 저장하고, 해시가 바뀐 이슈만 재생성한다. 상태 필드는 `none | pending | done | quota | no_evidence`.
- **동기 I/O**: Firestore를 호출하는 핸들러는 `def`(FastAPI가 스레드풀에서 실행)로 바꾸거나 `run_in_threadpool`로 감싼다. 이벤트 루프를 막지 않는다.
- **캐시**: 성공 응답은 `Cache-Control: public, s-maxage=300, stale-while-revalidate=3600`, 오류 응답은 `no-store`.
- **리전**: `vercel.json`에 `"regions": ["icn1"]`.
- **정본 id 해석**: `resolve_issue_id(id)` 헬퍼 하나가 `merged_into`를 따라가며(최대 3단, 순환 방지), 상세·공유·오늘·소스 목록이 모두 이 헬퍼를 쓴다.

### 6.1 이슈 상세 지연 (`services/issue_service.py:57-98`)

- 기사 조회를 순차 `get()`에서 `db.get_all(refs)` 일괄 조회로. 반환 순서는 요청 순서로 재정렬한다(`get_all`은 순서를 보장하지 않는다).
- 상세는 기사 **최신 30건**만 포함. 나머지는 `GET /api/issues/{id}/articles?cursor=`.
- **구 앱(Android v13) 호환**: `source_panels.{government, assembly_bill, assembly_vote, party}`, `perspectives`, `articles`, `events`, `official_links` 필드는 **형태를 유지**한다. `source_panels.media`만 제거(구 앱은 이 키를 읽지 않음). 새 필드(`digest`, `records`, `timeline`)는 추가만 한다. 구 필드 정리는 v14가 프로덕션에 올라간 뒤 30일 이후 별도 작업.
- 목표: 기사 50건 이슈의 상세가 **웜·캐시 미스 p50 2초 이내**. 콜드 스타트와 CDN 캐시 적중은 따로 측정·보고한다.

### 6.2 이슈 문서에 `digest` 사전 계산

파이프라인 끝의 `refresh_issue_digest` 단계가 **그 실행에서 변경된 이슈만** 갱신한다. 계산 입력은 이슈 문서의 `article_meta`(아래)와 그 실행에서 이미 로드한 소스 문서다.

```
article_meta: { <article_id>: { source, leaning, at } }   // 기사 연결 시점에 함께 기록. 기사 재조회 불필요
digest: {
  counts: { gov, bill, vote, media },
  has_official, has_vote, has_gov,                          // 필터용 bool
  vote: { source_id, bill_name, date, yes, no, abstain, result } | null,  // 대표 표결 = 연결 표결 중 최신
  stance: [ { actor, actor_type, position, basis, evidence, url, source_id, at } ],  // 최대 6
  bias: { left, center, right, foreign, unknown },
  last_activity_at,                                         // 연결 소스·기사 중 최신
  rank, rank_at
}
```

- `article_meta`는 기존 이슈에 대해 일회성 backfill(기사 2,884건 1회 읽기)로 채운다.
- `list_summaries`: `digest`를 반환하고 Firestore에서 정렬·필터·커서 페이지네이션한다. 지원 조합과 복합 인덱스(`firestore.indexes.json`에 기록):
  - 정렬 `rank` / `last_activity_at` / `counts.media` 각각 단일 필드 내림차순 + `id` 보조 키
  - 필터 `has_official`, `has_vote`, `has_gov`, `status` 각각 × 위 정렬 3종 = 복합 인덱스 12개
  - 필터는 한 번에 하나만 적용(UI 칩도 단일 선택). `merged_into`가 있는 문서는 쿼리에서 제외(`merged_into == null` 조건 대신 `active: true` 필드를 두고 인덱스에 포함).
- `rank`: 수동 이슈 가산 유지. 뉴스 이슈 = `min(newsworthiness, 20)` + 표결 있음 6 + 법안 3 + 정부 2, 여기에 `last_activity_at` 기준 72시간 반감 감쇠. 상한 40. 시간 감쇠는 매 실행마다 다시 쓰면 쓰기 폭증이므로 **`rank`는 활동 변화가 있을 때만 재계산**하고, 조회 측에서 `rank_at` 기준으로 감쇠를 적용해 정렬은 서버 `rank` 내림차순을 그대로 쓴다(근사치 허용).
- `stance` 생성 규칙(근거 유형 `basis` 필수):
  1. `basis=official`: 연결된 `gov_policy`의 AI 보강 `position`과 `claim_summary`. actor는 제목·발췌에서 **부처명 사전**(기획재정부, 보건복지부, 국토교통부 등 중앙행정기관 목록을 `utils/ministries.py`에 상수로)과 정규식으로 찾고, 없으면 "정부". `actor_name` 상수는 쓰지 않는다.
  2. `basis=vote`: 대표 표결의 `party_breakdown`에서 정당별 `{yes,no,abstain}`. position은 다수결이 아니라 **관측치 그대로**(UI가 "투표자 중 찬성 N·반대 M"으로 표시). 표결 참여 정당 최대 4개.
  3. `basis=press`(기본 비활성, `STANCE_PRESS=1`일 때만): 1·2가 모두 비고 보도 5건 이상일 때 Gemini 1회로 기사 제목·요약 상위 10건에서 `{actor, position, evidence(인용 또는 제목), article_id}` 최대 4건 추출. 예산 규칙은 §6.0. 행과 오늘 화면에는 쓰지 않고 상세 입장표에만 쓴다.
  4. 법안 소스(`actor_name="국회"`, `position="propose"`)와 정당 언급 그룹은 입장이 아니다. 넣지 않는다.

### 6.3 뉴스 이슈 중복 방지와 병합 (`services/news_issue_service.py`)

- **생성 시 대조**(기존 `news:` 건너뛰기 `:77-79` 제거). 새 군집을 기존 뉴스 이슈와 비교해 아래를 **모두** 만족하면 기존 이슈에 기사만 합친다.
  - 대표 인물(빈도 1위)이 같다
  - 기존 이슈의 `last_activity_at`이 14일 이내
  - 그리고 다음 중 하나: `article_ids` 겹침 ≥ 0.3(분모는 작은 쪽) **또는** 한쪽 인용구(4자 이상)가 다른 쪽 인용구를 포함
- 제목: 인물은 **군집 내 언급 빈도 1위**. 인용구가 그 이름을 포함하면 이름 제거.
- **일회성 병합 스크립트** `scripts/merge_duplicate_issues.py`: 같은 기준. §6.4의 크로스링크 정제를 먼저 적용한 뒤 돌린다(오염된 연결이 병합 근거가 되지 않게). 가장 오래된 이슈를 남기고 기사·이벤트·소스 관계·`article_meta`를 이관, 흡수된 문서에 `merged_into`·`active=false`. 대상 이슈에 `merged_into`가 있으면 병합 대상에서 제외(순환 방지). 실행 전 대상 문서를 JSONL로 덤프. **`--dry-run`이 기본이고, dry-run 보고서(병합 쌍 목록)를 사용자가 보고 승인한 뒤 실행한다.**

### 6.4 기사 연결 정제 (`services/source_link_service.py:63-104`)

- 뉴스 이슈의 `crosslink`는 **인명 단독 일치로 붙이지 않는다**. 인용구 토큰 2개 이상 또는 인용구 전체 일치가 필요.
- **기존 연결은 지우지 않는다.** 상한은 신규 추가에만 둔다(실행당 이슈별 12건 유지, 누적 상한 없음). 표시는 §6.1의 30건 페이지로 제어하고, 보도 분포 통계는 `article_meta` 전체로 계산한다.
- 매칭 로직은 순수 함수로 분리해 테스트한다.

### 6.5 요약 덮어쓰기 버그

- `news_issue_service.py:117-118`, `issue_cluster_service.py:102-104`의 갱신 패치에서 `summary` 제외. AI 요약이 아직 없을 때의 `summary`는 **규칙 기반 대체 요약**으로 쓴다: 뉴스 이슈는 연결 기사 중 중도 성향(연합뉴스·뉴시스·뉴스1·KBS 등) 최신 기사 제목, 없으면 최신 기사 제목. 법안 이슈는 `"{law_name} · {단계 또는 표결 결과} · {날짜}"`. "여러 매체가 보도한 현안입니다" 같은 템플릿 문장은 어디에도 쓰지 않는다. 기존 `template_summary` 필드는 두지 않는다.
- AI 요약 생성·재생성은 §6.0의 예산과 근거 해시 규칙을 따른다(기사 집합이 크게 바뀐 이슈만 재요약, 해시 비교). 기존 템플릿 상태 이슈는 backfill에서 대체 요약으로 바꾸고 `ai_summarized=False`로 되돌린다.

### 6.6 뉴스 이슈에 법안·표결·정부 발표 연결

- `source_items`에 **관계별 정본** `links: [{issue_id, status, score, reason, at}]`를 추가하고, 조회용 파생 배열 `issue_ids`(status가 `auto`·`confirmed`인 것만)를 유지한다. 기존 `issue_id`·`link_status`는 첫 관계의 미러로 남겨 구 코드 호환.
- 검수 API(`/api/sources/{id}/review`)는 관계 단위(`issue_id` 지정)로 승인·거절한다. 거절된 관계는 재연결 대상에서 제외한다.
- **자동 연결(`auto`) 기준은 정확 일치만**: 이슈의 기사 제목+요약 합본 텍스트에 소스의 `law_name` 전체 문자열(4자 이상) 또는 `bill.bill_name`이 그대로 포함될 때. 제안자∩인물, 정부 발표 명사구 같은 약한 신호는 `pending` 후보만 만든다.
- 법안 이슈 생성의 선점(`link_status=auto`)은 유지하되, 뉴스 이슈 링커는 "이 이슈와의 관계가 없는 소스"를 대상으로 돈다. 스캔 범위는 **최근 14일 소스를 `published_at` 커서로**(`limit(200)` 무순서 제거).
- 의원 상세: `GET /api/members/{id}`가 각 표결에 `issue_id`를 붙인다. 법안 이슈 id는 결정적(`issue_bill_{bill_id}`)이라 존재 여부만 `get_all`로 일괄 확인하고, 해당 법안 소스의 `links`에 수동 이슈가 있으면 그쪽을 우선한다.
- 자동 연결은 **표본 검수 후 활성화**: dry-run으로 뽑은 자동 연결 후보 20건을 사용자가 보고 정밀도 0.9 이상일 때 켠다.

### 6.7 판(edition) 문서와 오늘 API

- 파이프라인 끝에 `build_edition(date=KST 오늘)`이 `editions/{YYYY-MM-DD}` 문서를 upsert한다. **지난 날짜 판은 다시 쓰지 않는다**(고정). 내용:
  - `top_issues[≤3]`: `{id, title, summary, status, category, digest 일부(counts, vote, stance[official|vote만])}` 스냅샷. 선정: 그날 `last_activity_at`이 속한 이슈 중 `rank` 상위.
  - `assembly`: 그날 `assembly_vote`(법안명, 수치, 결과, procedural, issue_ids)와 그날 발의 `assembly_bill`(법안명, issue_ids). id와 표시 필드만.
  - `government`: 그날 `gov_policy`(제목, url, issue_ids). 부처는 없으므로 "정부"로만 표시.
  - `other_issue_ids`: 그날 갱신된 나머지 이슈 id 순위순(≤30).
  - `overview`: 그날 일일 요약 overview 또는 null.
- `GET /api/today?date=` → 판 문서 1회 읽기 + `other_issue_ids` 일괄 조회. 판이 없으면 `top_issues=[]`로 응답하고 프론트는 이슈 피드로 바로 이어 간다. 날짜 경계는 KST, 소스의 `published_at` 기준. 기사 수집 시각은 쓰지 않는다.
- 과거 판 backfill은 하지 않는다. 배포일부터 쌓인다.

### 6.8 소스 목록 API(둘러보기)

- `GET /api/sources?type=assembly_vote|assembly_bill|gov_policy&cursor=&limit=30`(공개, 읽기 전용). `published_at` 내림차순 + id 보조 키 커서. 응답은 표시 필드와 `issue_ids`만.
- 기존 `/api/sources/pending`·`/review`는 관리자 키 유지.

### 6.9 테스트

- 순수 함수로 분리해 pytest 고정: rank·stance 규칙(6.2), 중복 판정(6.3), crosslink 매칭(6.4), 정확 일치 링커(6.6), 판 선정(6.7), `resolve_issue_id` 순환 방지, 커서 인코딩.
- 서비스 계층: Firestore 가짜 객체로 `get_detail` 일괄 조회 경로, `list_summaries` 정렬·필터·커서 경로, `/api/today` 판 없음 경로 각 1개.

## 8. 배포 순서와 완료 기준

**순서(호환 우선)**
1. 백엔드 1차: 추가 필드만 쓰는 변경(`article_meta`, `digest`, `links`/`issue_ids`, `active`, `editions`)과 **호환 읽기**(새 필드 없으면 구 경로). 상세 일괄 조회·캐시·리전·동기 I/O 수정 포함. 구 응답 형태 유지. 배포.
2. backfill 스크립트: `article_meta`·`digest`·`active`·요약 플래그. 실행 후 건수 대조.
3. 정제·병합: crosslink 규칙 적용 → 병합 dry-run 보고 → 사용자 승인 → 실행. 자동 연결 후보 20건 표본 검수 → 승인 시 활성화.
4. 백엔드 2차: 목록 쿼리를 `digest.rank`·커서로 전환, 오늘 API·소스 목록 API 활성화. 배포.
5. 프론트 배포(Firebase). 구 Android 앱은 구 API 경로가 유지되므로 계속 동작.
6. Android `bundleRelease`(versionCode 14 / 1.2.0) → 서명 → Play 업로드(사용자).

**완료 기준**
- 백엔드: pytest 전체 통과. 상세 응답을 콜드/웜 × 캐시 적중/미스로 각 5회 측정해 보고, 웜·미스 p50 ≤ 2초. 파이프라인 1회 읽기 수를 로그로 남겨 2,000 이하 확인.
- 데이터: 병합 후 동일 대표 인물·인용구 포함 쌍 0건. 자동 연결 표본 20건 정밀도 ≥ 0.9. 상위 20 이슈 중 공식 기록이 붙은 이슈 수를 before/after로 보고(합계가 아니라 이슈 수).
- 프론트: `CI=false npm run build` 성공. Playwright로 모바일(390×844)·데스크톱(1280×900) × 라이트·다크 × 라우트 7개 + 상세 열린 분할 화면 스크린샷을 직접 판독. 금지 값 grep 0건. 렌더링 폰트 크기 분포가 7단계 안이고 12px 미만 0건. 200% 확대에서 가로 오버플로 0. 키보드만으로 목록→상세→닫기→포커스 복귀.
- 호환: `/?issue=<id>` 공유 링크(병합된 id 포함)가 상세로 열림. Android 뒤로가기 4단계 규칙 동작. 로그인·마이페이지 회귀 없음.
- 교차 검토: 구현 PR마다 codex 리뷰 1회.
